vLLM 0.31.0 adds an upper limit on the Transformers version in its requirements

3 October 2026

The vLLM project released version 0.31.0 on 2 October. vLLM is a library that serves large language models, which means it runs a model so other programs can send it requests and get answers. The main change in this release is small but practical. vLLM now sets an upper bound on the version of Transformers it accepts in its requirements file. Transformers is the Hugging Face library that holds the model code vLLM builds on, and an upper bound means the installer will refuse a version newer than the one vLLM was tested with. Without that limit, a fresh install could silently pull a brand new Transformers release and break your serving setup. So installs become more predictable, and you are less likely to lose an afternoon to a dependency you did not choose to upgrade. The fix was written by Isotr0py with Harry Mellor, and was cherry picked from commit 58b3298 on the main branch into this release.

Zig 0.17.0 released with a reworked build system and a new ELF linker

3 October 2026

Zig, a programming language and toolchain for writing low-level software, has released version 0.17.0. The release holds five months of work: 925 commits from 206 different contributors. The two biggest changes are a reworked build system, which now includes the Build Server Protocol, a standard way for editors and other tools to talk to a build system, and a much stronger ELF linker, the part that joins compiled pieces into a final program on Linux. Because of the new linker, the Zig team expects incremental compilation, where only the changed part of your code is rebuilt, to work for everyone on x86_64-linux. That means faster rebuilds while you work. Many small pieces also moved or disappeared, so existing code needs edits: void{} syntax and errdefer capture are gone, the i0 type is removed, and fmt.allocPrint now lives on mem.Allocator. Target support shifted too. sparc64-linux now works better thanks to the new linker, loongarch32-linux was added, and powerpc-linux-gnueabi was dropped. The team also decided on many language proposals, a required step before Zig 1.0.

Futhark adds a #[cpu_function] attribute to keep some code off the GPU

3 October 2026

Futhark is a programming language for writing fast parallel code, and its compiler normally puts every array in GPU memory when you build for a GPU. That rule became a problem for a student project by Elias Smedegaard, who needed two steps in one program: first colour a graph with a greedy distance-2 algorithm, which is strictly sequential, then use that colouring for heavy parallel numeric work. Running the sequential step on the GPU was slow, so the Futhark team added a new attribute called #[cpu_function]. A function marked that way keeps its inputs and intermediate arrays in CPU memory, and copies only the final result to the GPU. If you write Futhark, you can now mix one sequential CPU step into a parallel program without paying a large cost, because the copy happens in bulk instead of per element. The attribute is admitted to be a sharp-edged hack, and similar bugs probably still hide in other parts of the GPU backends. The compiler also ignores the attribute when you map such a function, and the team plans to keep the attribute as a hint even after the compiler learns to choose memory placement on its own.

Ollama 0.35.1 adds Cloudflare's Clef decision models with image support

3 October 2026

Ollama, the tool that runs large language models on your own computer, released version 0.35.1. The release adds support for Clef and Clef Flash, two new open-source decision models from Cloudflare. A decision model does not write text back to you. Instead, you give it a state and a list of questions, and it returns a score for each question. Clef has 27 billion parameters and Clef Flash has 9 billion. Both are multimodal, which means a request can include images as well as text. You send the request to a new endpoint called /v1/systemone, and the images are shared by all the questions in that one request. So you can pass a screenshot and ask "Does this image contain Ollama?", and get back a number like 0.958 instead of a sentence you have to parse. That makes screenshot checks, content filters and routing logic much simpler to build. Three other changes help too. Models that use web search can now run up to ten searches per response, up from three. Modelfiles now accept CAPABILITY declarations, so a model creator can state plainly what the model can do, and the declaration survives when you build from GGUF or safetensors files, inherit from another model, or export the Modelfile. And ollama show now reports only "decision" as the capability for decision models, so your client will stop offering them for normal chat, tools or thinking. The release also updates llama.cpp and the MLX engine.

ServiceNow builds AutoSynthData to generate training data for enterprise AI agents

2 October 2026

ServiceNow CoreAI released AutoSynthData, a pipeline that makes training data for AI agents that work inside a company's own systems. It works like this. First it runs the target model on diagnostic tasks and finds where the model fails. Then it runs a stronger teacher model on the same tasks to see what success looks like. From that gap it writes capability specification cards, and a generator uses those cards to build brand new tasks. Each task has three parts: a system specification, which is the rules and starting state; a user prompt, which is what the user asks for; and a verifier, which is the code that checks if the agent really finished the job. Every generated task is run in the environment first, and only tasks that pass are kept. The team showed the pipeline using EnterpriseOps Gym and its released dataset. If you fine-tune agents, hand-writing tasks and checkers is the slow part, and AutoSynthData automates that loop while shifting the training set toward what the model still gets wrong.

Ai2 releases Olmo-core 3, open training code for trillion-parameter MoE models

1 October 2026

Ai2 has released Olmo-core 3, an open framework for training large language models. The new version focuses on mixture-of-experts (MoE) models, which hold many specialised parts called experts but only use a few of them for each piece of text. In one test, Ai2 grew the expert pool from 8 to 128 while still picking only four experts per token, so active parameters stayed near 3.2 billion but total capacity rose from 4.6 billion to 47 billion, and training speed dropped less than 5 percent. The old version used fully sharded data parallelism (FSDP); the new one uses distributed data parallelism (DDP) and keeps experts sitting on the GPUs. On eight NVIDIA B300 GPUs, a 47-billion-parameter MoE ran at 52,000 tokens per second per GPU, up from 19,400 before, about 2.7 times faster. For developers, that means a smaller lab can now train big sparse models without NVIDIA Megatron-Core. Support for MXFP8, a lower-precision number format, added about 21 percent more throughput over BF16 and cut peak active memory from 103 GiB to 95 GiB. Ai2 also benchmarked a 1.2-trillion-parameter model across 512 GPUs, and says Olmo-core 3 is one of the systems behind the next generation of Olmo models.

Cloudflare launches K2, a serverless event streaming service, in public beta

1 October 2026

Cloudflare has launched K2 in public beta. K2 is an event streaming service, which means it sits between the programs that send data and the programs that read it. You send events to a K2 stream, and K2 stores them as an ordered log, so nothing is lost even if a reader is offline for a long time. Many readers can read the same stream at their own pace, or split the work between them. Under the hood K2 builds a partitioned log on top of R2, Cloudflare's object storage, so it scales to very large volumes and keeps old data cheaply. This means you can get durable streaming without running and tuning an Apache Kafka cluster yourself. The trade-off is speed on writes: about one second of produce latency at the 99th percentile. K2 is for high-scale data movement and fan-out reading, while Queues remain better for single work items that need retries and delays, and Basin Pipelines is the choice when events end up in R2 or Iceberg tables. Streams can be created with cf, Wrangler, the dashboard, or the API, and Cloudflare says a technical deep dive on the design is coming.

p5.js adds compute shaders so beginners can learn GPU programming

27 September 2026

Dave Pagurek, one of the developers of p5.js, has added compute shaders to p5.js. A compute shader is a small program that runs on the graphics card and does general math work in parallel, not just drawing pictures. This follows an experimental WebGPU build of p5.js released earlier in 2026, plus performance work and many bug fixes. The new shader system is called p5.strands. The idea is scaffolded learning, which means hiding the hard parts until the student needs them. Normally, GPU programming asks you to learn the shader pipeline, uniforms and a new shader language first. Drawing one triangle in Vulkan from scratch can take thousands of lines of code. With p5.strands you only need loops, variables, functions and basic JavaScript math. You write a plain function, call buildFilterShader, and set colors with a filterColor object, where color values run from 0 to 1. You can use familiar p5.js tools like noise() and millis() inside it. The WebGPU build is still marked experimental.

Valve adds Pyrowave, a low latency video codec, to the Steam client beta

27 September 2026

Valve has added a new video codec called Pyrowave to the Steam client beta. A codec is the software that compresses video before sending it over a network and unpacks it on the other side. Pyrowave is built for Steam Remote Play, the feature that streams a game from one machine to another, and its main goal is very low latency, which means very little delay between your input and the picture. Pyrowave is a wavelet codec, and it runs on the graphics card using Vulkan compute shaders instead of the fixed video encoder chip. Each frame is compressed on its own, so the codec never waits for other frames. If you build or test streaming, remote desktop, or cloud gaming tools, Pyrowave is a working open example of this design, and the code is public. Pyrowave is still marked beta, so you must turn it on yourself in the Steam client beta, and Valve is gathering feedback before a wider release.
