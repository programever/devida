DoorDash cuts grocery reorder time from 16 seconds to 2 seconds using AI agents

30 October 2026

DoorDash rebuilt the way its app rebuilds a grocery shopping list, and the wait dropped from 16 seconds to 2 seconds. The new way of working starts before the user opens the app. A batch job runs a large language model (LLM), which is an AI model that works with text, over past orders to guess what a customer buys again and again. The guesses then pass through deterministic validation, meaning plain rule-based checks that do not involve AI, so bad items get thrown out. The lesson for your own work is clear: move the slow AI step out of the request and into a batch job ahead of time, then use rules and fresh data to keep the result correct. DoorDash reports shopping list views doubled and the order rate from that flow rose about 34%.

Cloudflare makes services for private origins generally available to all customers

30 October 2026

Cloudflare has opened up its private origins feature to every customer, after a closed beta that started in June. An origin is the server that actually holds your application. Normally Cloudflare needs that server to have a public address on the Internet. Now you can point a proxied DNS record, which is a record that tells the Internet where your domain lives, at a private IP address like 10.0.0.50. Cloudflare then reaches your server over your existing Cloudflare One connection, using IPsec, GRE, CNI, Cloudflare Tunnel, or Cloudflare Mesh. A few things are missing: Argo Smart Routing and Dedicated CDN Egress IPs do not work yet, and origin health checks need Load Balancing. Cloudflare is now building private-to-private traffic and plans a closed beta in early 2027.

Go 1.28 HTTP/2 parking cuts memory by about 40% with 5,000 idle connections

30 October 2026

Go 1.28, the next version of the Go programming language, changes how its HTTP/2 server handles open connections. Before, every connection kept one goroutine, which is a lightweight Go thread, alive and waiting even when nothing was happening. The new internal mechanism, called parking in the Go source code, lets that goroutine exit when there is no work ready. A new goroutine starts again when work arrives. A developer measured the effect on a Linux machine with an Intel Core i7-1265U chip. With 5,000 idle connections, resident memory dropped by 84.7 to 92.6 MiB, which is about 38.9% to 41.4%. Goroutine count fell from about 10,007 to 5,007, and goroutine stack memory went from about 99 MiB down to about 21 MiB. If you run a Go server that holds many open but quiet connections, such as a mobile backend or a gRPC service, you get this saving for free after upgrading, with no code change. Heap memory did not improve in a consistent way, so do not expect every memory number to drop. The test used a development build of Go 1.28, not the final release, and the GODEBUG=http2serveparking=0 switch used to turn parking off is temporary and undocumented.
