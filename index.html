Ollama 0.40.6 fixes leftover Windows processes and adds q2_0 model file support

17 October 2026

Ollama, a tool that lets you run large language models (LLM) on your own computer, has released version 0.40.6. The release has four changes. On Windows, Ollama no longer leaves behind orphaned runners, which are model processes that keep running after they should have stopped. Ollama now supports the q2_0 tensor and file types in GGUF, the file format that holds model weights on disk; q2_0 stores each number in about two bits, so the model file is much smaller. A feature called clef was launched in Ollama's cloud. The --ask mode now uses identifiers for its question keys instead of the question text. The Windows fix matters most in daily work, because orphaned runners hold on to memory and graphics card memory and can block the next model you try to load.

vLLM ships version 0.32.0 with a macOS build fix in the Rust frontend

18 October 2026

The vLLM project has published release v0.32.0. vLLM is an open source library that serves large language models, which means it runs a model and answers requests from other programs. The change named at the top of these release notes is a bug fix in the Rust frontend, the part of vLLM written in the Rust language that accepts incoming network connections. The fix makes that code read the address family of a listener socket it was handed by the operating system, instead of assuming one. A listener socket is the open port that waits for connections, and the address family tells it whether the address is IPv4 or IPv6. Before the fix, the build failed on macOS. If you develop or test vLLM on a Mac, you can now compile it again. The full list of changes sits in the release notes on the vLLM GitHub page.

16 October 2026

Elorian, a startup in Palo Alto, released its first model on Friday. The model is called Glimpse, and it is a research preview with access through an application programming interface (API). A chat interface exists too, but only by waitlist. Most multimodal models, which are models that handle images as well as text, look at a picture one time and then reason about it in words. Elorian says Glimpse beats GPT-6 Astra on scientific chart reasoning and on short video captioning, but those numbers come from Elorian itself and nobody outside has checked them yet. Chief executive Andrew Dai said the goal for next year is a model that leads every visual reasoning test, and later a model that can control robots directly.

gopls v0.24.0 adds interactive refactoring that asks you questions before editing code

16 October 2026

The Go team shipped interactive refactoring in gopls, which is the language server for Go. A language server is the background program that gives your editor features like autocomplete and quick fixes. Until now, almost every refactoring in the Language Server Protocol (LSP) took no input, so gopls had to guess what you wanted. The new capability, proposed to the LSP standard and designed together with the Dart team, lets the server show multi-step dialogs and ask you for input first. You need gopls v0.24.0 and the official Go extension for VS Code v0.56.0. In practice, "Add struct tags" now asks which tags you want, such as json, yaml or db, and which naming style, such as camelCase or snake_case. Because the dialogs live in the protocol, editors like Neovim and Emacs get the same features without custom code. The proposal is still open in the LSP repository, and Move Declaration and Change Signature are tracked as future refactorings.

Rust 1.99.1 released with a fix for broken FFI bool return values on x86_64

16 October 2026

The Rust team shipped Rust 1.99.1 on 16 October 2026, a small patch release with three fixes. The compiler, rustc, no longer miscompiles bool return values in FFI calls on x86_64, where FFI means a foreign function interface, the way Rust code calls into code written in another language like C. The standard library now provides the missing wcslen symbol on UEFI targets and on embedded targets, so programs for firmware and small devices link correctly again. The bundled linker, rust-lld, also adds the rpath for libLLVM on macOS, so it can find that shared library at run time. The FFI bool bug is the one to act on: if you call C code from Rust on a 64-bit Intel or AMD machine, a function returning a bool could give a wrong answer, and a wrong answer there is very hard to debug. Update with rustup to get the fix.

Meta releases Muse Spark Open, an 816B open-weight model built for coding agents

15 October 2026

Meta has released Muse Spark Open, a free-to-download model aimed at agentic coding, which means the model reads a codebase, writes and fixes code, and calls tools on its own over long tasks. The model uses a mixture-of-experts design, where only a few parts of the model run for each word. Meta also ships an NVFP4 version, a 4-bit compressed copy with almost no accuracy loss, which fits on a single B200 node. Recipes for llama.cpp, vLLM and SGLang are already published, so smaller teams can try it through a hosted service instead of buying hardware.

Rust 1.99.1 released with fixes for link errors, FFI bool bug and macOS linker

15 October 2026

The Rust team has released Rust 1.99.1, a small point release that fixes three problems from earlier versions. The first problem was a missing function called wcslen, which measures the length of wide text strings. Some build targets could not find it and the build failed at the linking step, which is the stage that joins all the compiled pieces into one program. UEFI targets were completely broken for any project using the standard library. Rust now provides wcslen as a fallback. The second fix is a miscompilation of bool return values across a foreign function interface (FFI), the way Rust code talks to code written in other languages like C. On x86_64 machines, bits 1 to 7 of the return register were left unspecified, so the caller could read a value that was neither 0 nor 1. Rust now zero-extends that value as the rules require. The third fix makes rust-lld, Rust's own linker, load libLLVM correctly on macOS when the compiler runs without the rustup proxy. If you use UEFI targets, call Rust from C, or work on macOS, update now with the command rustup update stable. The Rust team also asks people to run the beta and nightly channels locally and in continuous integration, so bugs like these get caught before they reach a stable release.
