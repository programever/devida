Experiment finds AI agents cost 22 to 35% more to review unhealthy code

21 November 2026

Marcus Borg ran an experiment to see if clean code is cheaper for AI agents to work on, and Martin Fowler wrote about the results. The test used 465 pull requests, which are proposed code changes, from 246 open source projects. Each pull request went through a pipeline of five agents that reviewed the code and then fixed problems. Three different large language models (LLMs) were used. Code quality was measured with CodeHealth, a score from the tool CodeScene. A typical messy pull request scored 2.8 and a typical clean one scored 9.7. The messy code cost 22 to 35 percent more for the agents to handle. Two specific problems drove most of the extra cost: Complex Method and Complex Conditional. So cleaning up long functions and tangled if-statements now saves real money on every agent run, not just human reading time.

O'Reilly article maps the eight stages of an AI software factory

21 November 2026

An engineer writing for O'Reilly's Radar blog, republished on the Stack Overflow Blog, explains the software factory, which is a way of working where AI coding agents run the whole software lifecycle with very little human input. Raw work goes in, such as bug reports, feature ideas and incidents, and shipped software comes out. The factory has eight stages in three groups. First comes deciding what to build: triage sorts and routes incoming work, brainstorming looks for high impact features using user data and market research, and planning turns that research into a clear plan. Planning is called the most important stage, and there the agent reads the code in read-only mode, lets you be questioned about your choices, and records decisions in an Architecture Decision Record (ADR) log and a glossary. The output is tickets with documentation that a team of agents can build. Second comes building and checking: an engineer agent and a quality assurance agent work through the tasks, a review stage checks the pull request diff against product, architecture and code standards, a continuous integration stage runs the tests and sends failures to a fixing agent, and release pushes to staging and production with human deployment checks. Third is self-improving: production alerts, errors and incidents flow back into triage as new input. Running across all stages is the context layer, the data the agents can see. The author says a weak context layer limits what brainstorming and planning can even imagine, because a model with no examples just predicts the most common solution. One popular approach is the LLM Wiki, a term from Andrej Karpathy, which turns your data into a structured knowledge base made of plain files instead of a database. Factory offers this through its AutoWiki feature, and LangChain recently released OpenWiki, a command line tool for managing agent memory wikis. For your daily work, the useful idea is to stop chasing new labels like loop engineering or graph engineering and instead ask which of these eight stages you should automate, which you should buy, and where you should stay the human gate. The author built his own factory, called Squid, three months ago, and says the first version was so overbuilt he stopped using it, which is a warning that automating too much adds friction instead of value.

PostgreSQL 19 released, adds WAIT FOR LSN for read-your-writes on standbys

20 November 2026

PostgreSQL, a popular open source database, released version 19 on 19 November 2026. The release usually comes in September, but it arrived two months late. The team needed extra time to fix a large wave of security problems reported with the help of artificial intelligence (AI) tools. The new feature Simon Willison likes most is a command called WAIT FOR LSN. Many applications send writes to one main database, called the primary, and send reads to copies, called standbys. A standby can be a little behind, so a user can save a change and then not see it. With PostgreSQL 19 you first write your data, then ask the primary for its current write position with pg_current_wal_insert_lsn(), which returns a value like 0/0306EE20. You store that value, for example in a signed cookie. On the next request you run WAIT FOR LSN with that value, and the standby waits until it has caught up before running your query. You can add a timeout, such as 0.1 seconds, and you get an error if the copy is still behind. That means you no longer need to write this waiting logic by hand, the way Wikipedia did for MySQL.

21 November 2026

Meta has built Triton Low-Level Extensions (TLX). Triton is a programming language that lets you write GPU kernels, which are small programs that run on a graphics card, using simple Python code. Triton hides most of the hardware details for you. Hiding those details makes the code short and easy, but it also means you cannot control every step the graphics processing unit (GPU) takes. TLX gives that control back. TLX is a set of extensions inside Triton, so you write normal Triton code and then drop down to low-level commands only in the parts that need it. Meta's aim is to let a kernel use all the special features of new GPU chips. In day to day work, that can save you from rewriting a slow kernel in CUDA C++ just to make it fast. You keep the short Python version and tune only the slow part by hand. Sergio De Simone reported the work for InfoQ.

CSS scroll-state() lets you style pages based on scrolling, with no JavaScript

19 November 2026

CSS-Tricks published a guide to scroll-state(), a CSS container query. A container query is a rule that asks the browser a question about an element and only applies styles when the answer matches. scroll-state() asks four kinds of questions. The scrolled feature asks which direction the user last scrolled, like top, bottom, or block-end. The scrollable feature asks if there is still content to scroll past an edge. The stuck feature asks if a sticky element is now stuck to an edge. The snapped feature asks if an element is a snap target on the x axis, y axis, or both. You write it as an @container rule, not as a normal function. Jobs that used to need JavaScript now need only CSS. Hiding a navigation bar until the user scrolls up, sliding in a back-to-top link, or showing a scroll arrow that disappears at the end of the page all become a few lines of styling.
