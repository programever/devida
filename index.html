14 November 2026

DocumentDB has reached version 1.0, its first generally available release. Generally available means the makers say it is ready for real production use, not just testing. DocumentDB is a document database, which stores data as flexible JSON-like documents instead of fixed table rows. It is built on top of PostgreSQL, the well known open source relational database. DocumentDB speaks the MongoDB wire protocol, which is the language MongoDB clients use to talk to a server. So most MongoDB drivers, tools and queries work with DocumentDB without any code changes. DocumentDB uses the MIT license, one of the most permissive open source licenses, with very few rules about how you use the code. For you, DocumentDB is a way to keep writing MongoDB style code while running one PostgreSQL system, with one set of backups, monitoring and operations skills. Google open sources AQuA, a tool that finds why production AI agents fail

13 November 2026

Google has released AQuA, short for Ambient Quality Agent, as open source code. AQuA is a reference implementation, which means it is example code you can copy and adapt. AQuA works in three steps. First it reads real sessions from an AI agent that is already live and serving users. Then it checks if the same failure happens again and again, instead of only once. Last it looks for the root cause by comparing the failure against a snapshot of the source code that was deployed at that time. So AQuA helps the review and testing part of the work, but after release, not before. Google replayed 32 sessions of a travel booking agent. Developers then changed the prompts. Seat selection bypasses dropped from 15 sessions to two. Dietary preference omissions dropped from seven to zero. The gain for you is simple. Agent bugs are hard to see because the agent fails in soft ways, not with a crash. AQuA turns messy session logs into a short list of repeated problems with a likely cause, so you can fix the prompt instead of guessing.

13 November 2026

Thoughtworks built SpecBench, a platform that tests AI-enabled development workflows. A workflow here means the steps a team asks an AI agent to follow, from writing a specification, to planning, to breaking work into tasks, to writing the code, to checking the result. SpecBench runs a workflow on four kinds of tasks, which are frontend, backend, fullstack, and a command line application. SpecBench then scores the output on its own, and records the time, the tokens used, and the estimated cost. Thoughtworks shows older results from two runs on the same model, gpt-5.6-luna[max]. The steps are: feed the model your own material, such as documents, emails and chat logs; ask it to find single words and groups of words that often appear together as one term; ask it to flag both words that are new to it and familiar words used in a strange way; then have it write short dictionary style definitions; then let human experts fix the mistakes; then store the glossary in version control and refresh it on a schedule. IBM releases LLMON markup language in Granite 4.1 3B and 8B preview models

13 November 2026

IBM has created LLMON, short for LLM Object Notation and said out loud as "lemon". LLMON is a markup language, which means a way of adding tags to text so a program knows what each part means. LLMON was built for large language models (LLMs) instead of for parsers. Each part of a prompt gets its own tag, and the tags use special reserved tokens, so the model never confuses structure with normal text. Every block also gets a two-character ID, so one instruction can point at the exact data it should act on. IBM released two experimental preview models trained on it: granite-4.1-3b-LLMON-preview and granite-4.1-8b-LLMON-preview, plus a GitHub repository with a toolkit and example workflows. The practical win is safety. Hidden instructions buried inside user data, known as indirect prompt injection, are mostly ignored, and on some standard tests the attack success rate falls to nearly zero, while normal instruction-tuned models get hijacked often. You also stop fighting JSON. Converters turn existing JSON into LLMON and back without losing anything, and the tool Mellea already adds LLMON to its model calls automatically. Both models are still marked experimental preview, so treat them as something to test, not to ship.

12 November 2026

Google Cloud has released TPU Sync as open source. TPU Sync is a native C++ library, which means it is written in the C++ programming language and runs close to the hardware. The library moves two kinds of data around. The first is KV cache blocks. A KV cache is the memory a language model keeps about the words it has already read, so it does not have to do the same work twice. The second is model weights, which are the numbers that hold what a model has learned. If you serve models on Google TPUs, you now get a ready-made piece for this data movement instead of building your own. Faster weight loading and cache sharing means less waiting at startup and cheaper serving.
