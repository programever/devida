GNOME developer proposes Toolpak, a new way to install developer tools on image-based Linux

27 September 2026

A GNOME developer has published a proposal called Toolpak, a new system for installing developer tools on image-based Linux desktops. Image-based means the operating system ships as one read-only image, the way iOS, Android and ChromeOS do, instead of as many separate packages you can add or remove. Flatpak already solved how to ship normal desktop apps, but tools you run in a terminal are still a problem. The post walks through why every current answer falls short: rpm-ostree package overlays on Fedora Silverblue can break the system or stop it from updating, so the next Silverblue is moving to bootc and dropping them; a single monolithic developer overlay, like the one in GNOME OS, only covers the tools needed to build the OS itself; Toolbox and distrobox put you back on old package managers inside a container that debugging tools were never written for; and Homebrew has to put its own binaries ahead of the system ones, so installing QEMU can override the GLib the rest of your system depends on. Flatpak itself is worse here, because it expects apps to reach system files and devices through portals, which suits graphical apps and not command line ones. Toolpak aims to ship tools like strace, ripgrep and qemu independently of the host OS, so they cannot break it, while still letting them reach the resources they need. If you work on system components, drivers or the kernel, this is the piece that decides whether you can use an image-based desktop at all. Toolpak is still a design at this stage, and the author says the related questions of project build setups and sandboxing will be covered in later posts.

25 September 2026

The Effect team published This Week in Effect number 137. Effect is a TypeScript library for building programs that handle async work, errors and resources in a structured way. The biggest news is a large performance pass in the Effect v4 release candidate (RC), which is a near final version before the stable release. Liquid AI releases LFM2.5-VL-DSpark, a draft model that speeds up vision model output

24 September 2026

Liquid AI released LFM2.5-VL-DSpark, a small helper model that makes their LFM2.5-VL-3B vision-language model produce text faster. A vision-language model is a model that can look at an image and answer questions about it. The helper model uses speculative decoding, which means a small fast model guesses the next block of words and the big model only checks them. The helper has about 280 million parameters, so it adds only 8.9 percent to the size of the 3 billion parameter main model. On an Apple M5 Max using MLX, decoding is 2.30x to 3.13x faster, and total response time is 1.56x to 2.62x faster. On an H100 graphics card, decoding goes up to 2.66x faster. The output does not change, because the main model verifies every guessed token, so greedy results stay the same. Support is ready on day one for llama.cpp, MLX-VLM and SGLang, though each one still needs a build with the matching pull request, such as PR #40651 for SGLang. Speed gains are smaller on small images and short answers, because reading the image and the prompt is not made faster at all.

Docker launches Cloud Sandboxes so coding agents can run for hours in the cloud

24 September 2026

Docker has launched Cloud Sandboxes. Earlier this year Docker released Docker Sandboxes, which are microVM environments, meaning tiny isolated virtual machines where a coding agent can work without touching your real files, network or secrets. Cloud Sandboxes are the same microVM, but running on machines that Docker manages. You move a sandbox between your laptop and the cloud with one command, sbx move my-project --to cloud, and the filesystem is copied over so your work follows you. The reason to care is simple. Your laptop sleeps when you close the lid, so a task that runs all night dies with it. Now you can start an agent, walk away, and read the result in the morning, or run a hundred agents at once. Ready-made kits exist for Claude Code, Codex, Copilot, Antigravity, Open Code and Hermes. You need sbx version 0.45.1 or later and a pay-as-you-go plan on a Docker Personal or Pro account. Compute is billed by the second, a paused sandbox costs nothing, and sessions last one hour by default and up to 24 hours. New accounts get 250 dollars of free credit for a limited time. Central control for companies, called Docker AI Governance, is still listed as coming soon.

Docker publishes Sandbox Kit Specification v3, packaging agent permissions as an OCI image

24 September 2026

Docker released version 3 of the Docker Sandbox Kit Specification, open source under the Apache 2.0 licence, in a public repository called docker/sandbox-kit-spec. A Kit is a file that says what an AI agent is allowed to touch: network rules, credentials, volumes, ports, devices and tools. The big change in version 3 is that a Kit is now an ordinary OCI image, which is the standard image format that Docker and other registries already use. So a Kit builds with docker buildx build, pulls with docker pull, and gets scanned and signed by the tools you already run. The permissions live in one annotation on the image manifest, so pinning the digest pins the content and the permissions together. Today all of that lives in docker run flags, a Compose file, or someone's memory, and you cannot review it or compare it to last week. With a Kit you can read the permission list like a text file, and a Kit asks for access rather than granting itself any. A Kit can also block specific calls, for example allow most of the GitHub application programming interface (API) but deny DELETE on repository paths. The rules only bite if the runtime implements them, and Docker Sandboxes is the first runtime that does.

Cloudflare adds Vary header support to Cache Rules on all plans

22 September 2026

Cloudflare now supports the Vary response header inside Cache Rules, and the feature is available on every plan. Vary is a standard HTTP header that the origin server sends to tell a cache which parts of a request can change the answer, such as the language, the image format, or the compression method. The problem is that Vary says which fields may matter, but not which differences really matter. One URL can then explode into thousands of cache entries that hold the same bytes. Cloudflare looked at over 120 million responses from nearly 50,000 popular sites and found almost 3,000 sites varying on four or more fields, some on 10, 23, even 47. With the new control you pick the behaviour per header: normalize known negotiation headers, pass the exact value to the origin when the small difference is real, or skip the cache when the variation is too wild. So you stop copying your content negotiation logic into a custom cache key or a Worker, and you keep a warm cache without serving JSON to a browser by mistake.
