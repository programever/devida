Simon Willison says AI models that draw with code beat dedicated image models

29 November 2026

Simon Willison wrote about a new way of making pictures with AI. Instead of asking an image model for a finished picture, you ask a text model to write code that draws the picture. He started with a prompt in Google AI Studio asking Gemini 4 Neon to create an SVG poster, which is a picture made of code instead of pixels, about the Kakapo recovery project in a 1970s design style. He then sent follow-up prompts to fix problems, such as making the bird face more realistic and fixing text that did not fit inside a shape. The model also ran Google searches to find real facts for the poster, and Willison checked that the numbers were correct. This way of working helps the design and asset part of your job. The big win is editing. A picture made of code can be changed by hand in a text editor, or opened in Inkscape, Adobe Illustrator or Boxy SVG, or changed again by the model writing more code. Image models like Nano Banana or ChatGPT Images give you flat pixels, with strange glitches when you zoom in and fake-looking text. Willison says the same trick works for HTML and CSS, 2D Canvas drawings, Blender scripts and even game assets, because models like Claude Opus 5.5, GPT-6 Astra and Gemini 4 Neon write good enough code for them. He still recommends normal image models for photorealistic pictures. One small problem to know about: AI Studio does not show SVG files, so the model cannot see its own mistakes unless you send it a screenshot.

Thoughtworks shares a step by step way to add AI to software delivery

27 November 2026

Thoughtworks published a way of working for teams that want to use AI coding tools without breaking their delivery pipeline. The first step is a path to production mapping session, where the whole team draws every stage of work from writing a story to running code in production. The team then votes on the most painful stage, which is the bottleneck. The next step is to pick one small change for that bottleneck and run it for a single sprint. In the retrospective the team asks if work felt smoother and if releasing felt safer, then keeps the change or drops it. Thoughtworks also says to use AI to build the safety harness, meaning automated tests and build checks, not only product code. The method mostly helps the later parts of the journey: review, testing and deployment. The reason this matters is simple. AI does not fix a weak pipeline, it amplifies what is already there. Faster code generation with manual quality assurance (QA) just creates huge pull requests and long review queues. Thoughtworks points to the 2024 DORA report, where only 19 percent of teams deploy on demand with lead times under a day, while 60 percent sit in the medium or low tiers and ship once a week to twice a year.

Hugging Face generates video with LTX-2.5 on an AWS Trainium3 machine

27 November 2026

A Hugging Face engineer had one month of access to an AWS Trainium3 machine, called trn3.48xlarge, with 64 NeuronCores. NeuronCores are the small compute chips inside the machine that do the math for a model. In the last five days he used it to make short films with LTX-2.5, a model from Lightricks that makes video and sound at the same time. The first attempt needed about 5 minutes 20 seconds for a 10-second clip. After the work was done, a 10-second clip at 2048x1024 took 22 to 23 seconds on half the machine, once the models were loaded. That is about one second faster than the 23.7 seconds LTX reports for its own online service. The input is a JSON file that lists shots, like a storyboard. Each shot has a name and a long prompt about style, subject, motion, camera, light and sound. Shots link together with two keys, from and to, so a shot can start from the last frames of another shot or end on the first frames of a later one. That linking keeps the same character and motion across a cut, which prompts alone cannot do. Three diffusers pipelines share the model: LTX2Pipeline for plain shots, LTX2ConditionPipeline for linked shots, and LTX2LatentUpsamplePipeline to upscale before three final steps. Only about 160 lines of Python sit on top. For a developer, the useful part is that video generation is no longer tied to NVIDIA CUDA hardware alone, and that a simple shot file plus frame chaining is enough to draft a real scene. Making it run needed tensor parallelism and sequence parallelism to split the transformer across cores, because the model does not fit on one. The code is published in the dacorvo/video-generation repository, and three issues, including the transformer compile, are still unexplained.

Rust 1.100.1 released to fix an Iterator type inference bug

27 November 2026

The Rust team has released Rust 1.100.1, a small point release. Rust is a programming language used to build fast and reliable software. A point release is a small update that only fixes problems, with no new features. Rust 1.100.1 fixes one bug that came from the earlier Rust 1.100.0 release. In Rust 1.100.0, the team changed the unstable const version of Iterator. Iterator is the part of Rust that lets your code walk through a list of items one by one. Stable Rust code could not even use that unstable const version, but the change still broke things by accident. Some types that did have a valid Iterator implementation were no longer seen as Iterators by the compiler. So code that used to build could suddenly fail. The team has now undone that change. If your project stopped compiling after you moved to Rust 1.100.0, this update should fix it. You can get the new version by running rustup update stable. The Rust team also asks people to test the beta and nightly channels and report bugs, so these breakages get caught before they reach the stable release.

Rust 1.100 stabilises custom allocators after 10 years in limbo

27 November 2026

Rust 1.100 has finally stabilised the custom allocator API, which lets you choose how a piece of code asks the system for memory, instead of using one global rule for the whole program. The feature waited about 10 years before it was ready. A blog post by cetra3, shared on Lobsters, walks through two useful patterns. The first is a bump allocator: you reserve one big block of memory, for example 32 megabytes, hand out small pieces from it by moving a counter forward, and then free the whole block at once. The post shows building a chain of 1,000,000 nodes and dropping all of them in almost no time. The second pattern is memory accounting: you wrap an existing allocator in a thin counting layer, so you know how many bytes one part of your code is using. That number can then drive real decisions, like evicting items from a cache, sizing an external sort, or capping a sandbox that shares memory with other sandboxes. The API is a minimum viable product, so expect more parts to land in later Rust releases.

Microsoft team builds native CSS mixins into Chromium, behind an experimental flag

26 November 2026

Patrick Brosset wrote about CSS mixins, a new way to save a block of CSS code under a name and reuse it. A mixin is different from a CSS custom property, also called a CSS variable, because a custom property holds only one value, while a mixin holds many declarations and even nested rules. You write a mixin with the @mixin rule and use it with @apply, and the name starts with two dashes, like --visually-hidden. Mixins can take parameters with types and default values, so @apply --button(crimson) changes just one color. A mixin can also take a whole block of CSS from the call site, placed where you write @contents, and it can keep its own hidden variables inside an @private block. For you, this means less copy and paste in style sheets, and named breakpoints like --mobile, --tablet and --desktop kept in one place. Brosset says his team at Microsoft is getting Chromium ready to ship mixins. Today the feature is experimental, so you must open about://flags in a recent Chromium browser and turn on Experimental Web Platform features. Other browsers have not shipped it yet.

Postgres 19 adds pg_plan_advice and pg_stash_advice for query planner hints

26 November 2026

Postgres 19 ships two new contrib modules, which are optional add-on parts that come with the database. The first one, pg_plan_advice, works at the session level. You use a SET command to tell the planner, which is the part of Postgres that decides how to run your query, which choices it may make. You can set the scan method, the join order, the join method, parallelism, partitionwise joins and semijoin uniqueness. The second module, pg_stash_advice, does the same thing but attaches your advice to a query identifier, so the same hint applies every time that query runs. For years the Postgres community refused query hints, so this is a real change in direction. In daily work, it gives you a way to rescue a slow query without adding a new index. One test showed a query taking 1461 ms because Postgres threw away 10,000,000 rows before finding 10 matches. EXPLAIN now also takes a PLAN_ADVICE option that prints the advice matching the plan Postgres actually chose. Two warnings matter. The modules only remove options, so they cannot force the exact plan you want, and the advice will be ignored if no valid plan fits. Postgres also never checks whether your advice is good, so bad advice will quietly make a query slower.

GitHub shows an evidence-first workflow for picking the next safe modernization step

25 November 2026

GitHub published a way of working for updating old applications, and the first step is not choosing a new framework. Instead you build an evidence inventory: the manifest files, the lockfiles, the commands that really install, build, test and run the app, the pinned runtime versions, and the outside contracts like APIs and file formats. You mark every item as documented, inferred or unverified, so a guess never becomes a finding. Then you decide component by component, starting with the smallest change: keep it, upgrade it, swap it, wrap it, or rewrite it only when no safe upgrade path exists. After that you run a time-boxed feasibility check, which is a short try at building and starting the component, and the result picks your path: record the old behavior and then upgrade, or build one thin modern slice first. The method was tried on four public applications, from a small Node.js game to a large Java enterprise resource planning (ERP) system. One of them, PiggyMetrics, ran Java 8, Spring Boot 2.0.3, Spring Cloud Finchley, Zuul and Hystrix, and looked dead; the nine test errors traced to an embedded MongoDB download returning HTTP 403 and an i386 binary that cannot run on Apple Silicon, not to broken business code. The practical gain is that this work sits in the planning stage, before any code changes, so you stop rewriting things that still work. GitHub also packaged the procedure as a GitHub Copilot agent skill called doc-and-modernize, so Copilot can collect the evidence while the architecture decisions stay with your team.

Thoughtworks team builds Code Argus, an agentic DevSecOps tool for CI pipelines

25 November 2026

A three-person team at Thoughtworks built a tool called Code Argus during the AI/works Innovation Hackathon in 2026. Code Argus is an agentic DevSecOps workflow, which means a chain of small artificial intelligence (AI) agents that work inside your build pipeline. The flow starts when a finding arrives, such as an alert or a pull request. First a knowledge base gathers real evidence about the code. The knowledge base uses Neo4j, a graph database, to answer who calls a function, and pgvector to find code that looks like a stack trace. Then a Fix agent proposes a change. Then real test and security runners check it, and a red build loops straight back to the Fix agent. So the tool helps the review, testing and deployment part of the journey, not the idea part. For your day to day work, the point is that your engineering standards get applied the same way to every pull request, and the agents cite the file and line they used instead of guessing. The team runs Code Argus as a container invoked by a GitHub Action, so it costs nothing while idle. They chose LangGraph for the agent layer and LiteLLM to stay free of one model provider, with Google's gemini-flash-latest as the Critic model. Code Argus is still an experiment, so treat it as a design pattern you can copy rather than a product you can install today.

Ai2 released RoboTrack, a test set and training data for point tracking in robot work. Point tracking means you mark one spot in a video frame, and a model follows that same spot through the later frames, including when something hides it. RoboTrack-Bench holds 307 videos with 2,522 point tracks, all marked and checked by people, taken from DROID, Ego-Exo4D, MolmoAct 2 and EgoVerse. The videos show robot grippers and human hands in messy scenes, from both first-person and third-person cameras. Four strong trackers, CoTracker3, BootsTAPNext, AllTracker and CoWTracker, all scored lower here than on the older RoboTAP test, by 3.0 to 6.6 points of Average Jaccard. CoWTracker fell from 70.5 to 63.9. Ai2 also built RoboTrack-15M, a synthetic training set of 15 million point tracks made in its MolmoSpaces simulator, and training on it lifted scores on real video. If you work on robot perception, the lesson is that good scores on old tabletop tests do not prove a tracker is ready for real rooms, so retest your own tracker here. Two new models are out now, RoboTracker and RoboTracker-Warp, plus the paper, data and code.

Ladybird browser reaches alpha with downloads for macOS and Linux

23 November 2026

Ladybird, a web browser built on a brand new engine, has reached its alpha stage. An engine is the core part of a browser that reads web pages and draws them on the screen. The Ladybird team wrote their own engine from scratch, so it is not a copy or a fork of Chrome or Firefox. You can now download Ladybird for macOS and Linux. The browser around the engine is simple but it works. Because the release is an alpha, which means early and unfinished, some websites will not load and the browser will crash sometimes. If you build websites, you can open your own site in Ladybird and tell the team what breaks. Ladybird supports WebDriver for automated testing and the Firefox DevTools protocol for inspecting pages. The alpha is a rolling channel with regular automatic updates, so you no longer need to build Ladybird from source to see new work. The team makes no security promises yet and openly invites people to find and report holes.

Dev Material Archive saves old web development articles from disappearing

23 November 2026

A new website called Dev Material Archive collects written articles about web development, web design, and web accessibility that used to exist online but are now gone. The people behind the archive copy and store these old posts so they stay readable. CSS-Tricks wrote about the project and praised the work, which is still going on. The reason this archive is needed is link rot, which means a link points to content that was deleted or to a page that moved to a new web address. Old web writing disappears for many reasons. Publications shut down. Rights expire. Companies get bought. Websites get redesigned or move to a new content management system, which is the software that stores and publishes a site's pages. For you, the practical gain is simple. Old articles you learned from, or want to link to in your own notes and documentation, do not vanish. CSS-Tricks also points to The History of the Web, a long-running project by Jay Hoffman that preserves web history in a similar spirit.

Kubernetes v1.38 sneak peek lists kubectl removals and a cgroup driver breaking change

23 November 2026

The Kubernetes team published a preview of what is coming in Kubernetes v1.38, the next version of the popular system for running containers across many machines. Two kubectl settings go away. The environment variables KUBECTL_REMOTE_COMMAND_WEBSOCKETS and KUBECTL_PORT_FORWARD_WEBSOCKETS, which let you turn off WebSocket connections for commands like exec, attach, cp and port-forward, are removed. The name field in kuberc credential plugin allowlist entries is also dropped, so you must use command instead. The biggest change is about the cgroup driver, which is the part of Linux that limits how much memory and processor time a container can use. The kubelet, the agent on each node, will now ask the container runtime for that setting instead of reading it from its own config file. If your container runtime is old or not running first, the node will fail to start. Pods on nodes with LimitedSwap may also lose swap. Check your scripts and node setups before you upgrade, and read the official v1.38 release notes when they arrive.

Gliver, a Guile Scheme tiling window manager for Wayland, nears its 0.0.5 release

23 November 2026

Christopher Lemmer Webber wrote about switching to Gliver, a window manager built in Guile Scheme. A window manager is the program that draws and arranges the windows on your screen. Gliver is a tiling window manager, which means it splits the screen into panes instead of letting windows float on top of each other. Gliver works in the style of StumpWM and Emacs, and it runs on top of River, a Wayland compositor made as a framework for building window managers. Gliver is not in Guix yet, but there is an open patch request waiting for the next release, version 0.0.5, which fixes many bugs. What makes Gliver interesting for a developer is that it is live-hackable. Gliver opens a Unix domain socket in your home directory as a read-eval-print loop (REPL), which is a prompt where you type code and see the result at once. You connect to it with Geiser, an Emacs tool for Scheme, then inspect the running system, jump straight to the definition of any command, change the code, and apply the change without restarting. A built-in describe-key window shows which key runs a command, or which command a key runs. Gliver is still early, with real bugs and missing features, so expect to file issues. The 0.0.5 release is the thing that unblocks packaging in Guix.

Google announces Agent Compute Engine to run AI agents in isolated microVMs

22 November 2026

Google announced Agent Compute Engine, a managed service that runs AI agents inside isolated microVMs. A microVM is a very small virtual machine, which is a software computer that runs separately from everything around it. Each agent gets its own microVM, so one agent cannot touch another agent's work. The service also supports checkpointing, which means saving the full state of a running environment. With checkpointing you can suspend an agent and resume it later from the same point. Secrets stay outside the sandbox. Passwords, API keys and OAuth refresh tokens are held by a separate part called the Agent Gateway. The Agent Gateway checks each request and then injects the right secret. If you build agents, you no longer have to write your own sandbox or hand your keys to agent code that may run commands you did not plan. Suspend and resume also means a long task does not need a machine running the whole time.

PostgreSQL 19 released with online table repacking and query planning controls

22 November 2026

The PostgreSQL Global Development Group has released PostgreSQL 19. PostgreSQL is a free, open source database system. The new version brings changes in four areas: database maintenance, query planning, replication, which means copying data to other servers, and application development. The headline feature is online table repacking. Repacking means rewriting a table to remove wasted space and put the rows back in a tidy order. In older versions, repacking a big table usually meant downtime, so the table was locked and the application had to wait. In PostgreSQL 19 the table stays available while the work runs. The release also adds new controls over query plans. A query plan is the step by step path the database chooses to answer your question. Sometimes the database chooses a slow path, and now you can steer that choice. Day to day, this means fewer late night maintenance windows and fewer tricks to force a slow query to run fast.

Redis 8.12 released with compressed bitmaps and expiring Set members

22 November 2026

Redis, a popular in-memory data store, has released version 8.12 as a General Availability build, which means it is ready for production use. The biggest change is compressed bitmaps. Redis merged a project called redis-roaring into the core of Redis, so bitmap operations now use less memory and run faster. The original creator of redis-roaring, Antonio Viggiano, contributed the code. Large sorted sets also use much less memory thanks to a new B+ tree encoding. Redis 8.12 adds many new commands. SEXPIRE, SPEXPIRE and friends let you set an expiration time on a single member inside a Set, and STTL or SPTTL tell you how much time is left. BLESS protects chosen keys from being evicted when memory runs low. ZMOVE, BZMOVE and ZMOVEMEMBER move members between sorted sets in one atomic step. There is also a new BITRANGEINTARRAY command that returns the set bit positions inside a range. For your daily work, the memory savings can cut your server costs without any code change, and per-member expiration removes a lot of cleanup code you used to write by hand. The release also fixes real bugs, including wrong BITCOUNT results on AArch64 chips, which are the ARM processors used by many cloud servers. The new SQ8 compression for HNSW vector indexes stays opt-in, so you must turn it on yourself if you want smaller vector search indexes.

scriptura, a new fish shell tool to run and manage scripts in a folder tree

23 November 2026

Alan Pearce has released scriptura, a small command line tool that helps you run and organise your personal scripts. You put your scripts in one folder tree, for example ~/scripts, and you point the SCRIPTURA_ROOT variable at that folder. Then you type a command like scriptura run os update linde, and scriptura runs the script at ~/scripts/os/update/linde. The tool is written in fish, which is a Unix shell, and it gives tab completion for every part of the path, so you do not need to remember where each script lives. It also has subcommands to make a new script, edit a script, show the script path, print the script content, and run any shell command from the script folder. scriptura can read documentation from a .help file next to the script or from # comments inside the script, and show that text during completion. Many developers keep a messy pile of helper scripts and then forget the names, so a searchable tree with completion and built-in help saves real time. scriptura is based on an earlier idea called sd, but the author renamed it because sd clashed with another tool, and added fish completions, custom subcommands, and ad-hoc commands. Scripts default to a fish shebang line, and the author plans to add a command line option to choose a different interpreter.
