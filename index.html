Harvard study of 718 firms finds AI code tools add volume but not finished work

22 October 2026

Researchers at Harvard studied 718 companies using Jellyfish, which is an analytics platform that measures how software teams work. The study found that AI coding assistants and AI agents do make developers produce much more code. But the amount of finished, delivered work did not go up by the same amount. The reason is that the extra code creates extra work later in the process. Code review, which is the step where another developer checks the code before it is merged, becomes the biggest blocked point. So writing code faster does not mean shipping faster. If your team is adding AI coding tools, the slow part may move instead of disappearing, and your review queue, testing and release steps will feel the pressure. The practical lesson is to measure completed work, not lines of code, and to give review and testing more people or better automation before adding more AI output.

InfoQ article shows an AI data workflow where DuckDB computes facts and the agent reads them

22 October 2026

Peihao Yuan describes a way of working for disaster-recovery analytics, which means checking data about system failures and backups. The workflow has three steps in order. First, an AI agent writes limited SQL or Python code. SQL is the language used to ask questions of data. Second, DuckDB runs that code over Parquet files and produces the numbers. DuckDB is a small database engine that runs inside your own program, and Parquet is a file format for storing table data. Third, the agent only explains the numbers it gets back. Yuan calls this a determinism split: the engine does the exact maths, and the agent does the talking. The workflow helps mostly with writing code and with review, because every analysis can be replayed later and checked. Yuan also gives four signals for deciding when a small embedded engine is enough and when you should pay for a managed lakehouse instead.

Thoughtworks says ask AI to find missing decisions before writing user stories

22 October 2026

A Thoughtworks blog post describes a way of working that changes when you let AI write a user story, which is a short note that describes a feature from the user's point of view. The advice covers the planning stage, before any code is written. Step one is to give the AI assistant the user's task, the outcome they want, the rules you already confirmed, and your raw notes. Step two is to ask it to sort everything into three groups: confirmed, assumed, and unknown. For every confirmed item you also ask it to quote the exact source line. Step three is to tell it clearly not to invent business rules and not to write final acceptance criteria. Step four is to rank the open questions, using three checks: could the answer change the scope, change who is allowed to do what, or change what the data means. Step five is to bring those questions to a team meeting, such as refinement, Three Amigos, or Example Mapping. Only after people agree do you ask AI to draft the story. The reason this helps your day is simple. AI writes text that sounds certain even when nobody decided the rule, and the post calls these confident gaps. One example is an AI draft that adds "remove duplicate records" when the team never discussed duplicates. That hidden guess comes back later during development or testing, where fixing it costs much more. The post includes a ready prompt you can copy, and suggests you try the method on one real requirement and note which questions were useful and which were noise.

GitHub moved almost all repositories to Azure and now splits Git locks per branch

21 October 2026

GitHub has copied 99.99999% of the Git repositories it hosts into Microsoft Azure, starting with the first copy in Azure's Central US region in August 2025. Most repositories now keep two of their five replicas in Azure, and Azure serves about half of all Git traffic. The last few repositories are the busiest ones, and they are stuck because of a 25ms network round trip between GitHub's own data centers and Azure, about 1,000 miles away. Today a write takes a lock on the whole repository, so one slow replica slows every push. GitHub is changing that lock, called a quorum, so it covers one reference, which is one branch or tag, instead of the whole repository. In internal tests with real traffic, pushes to different branches ran 3 to 4 times faster. For you, pushes from several people, or from several coding agents working on their own branches at the same time, stop waiting in line behind each other. GitHub says the next step is storing repository data in Azure Blob Storage so read traffic, which is 100 to 1,000 times more common than writes, can scale on its own.

CSS random() function ships in Safari and rolls out in Chrome 156

20 October 2026

The CSS random() function is now in Safari and is rolling out in Chrome 156, with Mozilla sending positive signals for Firefox too. The function comes from the CSS Values and Units Module Level 5 specification, which is the official document that defines how these CSS features should work. You write it with simple comma-separated values, like rotate: random(-3deg, 3deg) for a small random tilt, or animation-duration: random(1.5s, 3s, 0.2s). The third value is an optional step size, so random(0px, 60px, 15px) only gives you 0px, 15px, 30px, 45px or 60px. Both bounds must use the same unit type, so you cannot mix rem and px. You can also pass a caching key, such as random(--square-size, 60px, 120px), to make two properties share the same random value and stay in sync. For you, this means small organic touches no longer need a JavaScript library or a Sass loop that generates hundreds of lines of static CSS. Brecht De Ruyte shows the idea in CodePen demos on Smashing Magazine, with tilted typography, bouncing letters and splayed cards.

TypeScript 7.1 Beta adds import attributes in ambient modules and source phase imports

21 October 2026

Microsoft released the beta version of TypeScript 7.1, which you can install with npm install -D typescript@beta. The first big change is support for import attributes inside ambient module declarations. An import attribute is extra information you attach to an import statement, written after the word with, like import myData from "./data/someData.json" with { type: "json" }. Before now, you had to declare one wildcard module per file extension, such as *.css or *.md, and TypeScript ignored the attributes completely. Now you can write declare module "*" with { type: "text" } and get the right type, plus an error if you forget the attribute. That removes repeated declarations for .txt and .md files, and it matches how runtimes and bundlers really behave, because a bundler may treat a .css file as CSS Modules unless type: "css" tells it otherwise. TypeScript 7.1 also supports source phase imports, written import source SomeModule from "some-module", which hands you a parsed but not yet linked module object. For WebAssembly files that object is a WebAssembly.Module, so you can pass it straight into WebAssembly.instantiate. Note that these wildcard declarations do not ship inside TypeScript, so you must write them in your own project, and imports matching them are not checked against real files on disk.

Linus Torvalds has released the final version of the Linux 7.3 kernel, the core software that runs Linux systems. Linux 7.3 is the biggest release so far by every count. It took in 18,765 commits, which are single saved code changes, from 3,021 developers. 807 of those developers sent kernel code for the very first time. The release adds many new things. There is a new fchroot() system call, and global per-CPU data for BPF programs, which run small safe programs inside the kernel. Virtual machines get working-set tracking, the ntfs3 filesystem gets alternative data streams, and the SMB file sharing server gets a long list of fixes. The sched_ext feature, which lets you plug in your own task scheduler, is now complete. A joke filesystem called failfs, which fails every operation, is also in. For a developer, sched_ext means you can test custom scheduling policies without patching the kernel, and the group-scheduling work should help performance on machines with many cores. The merge window for Linux 7.4 opens now, though Torvalds says his schedule will be unusual because he is on family vacation.

Deno team moves to Cloudflare and a developer starts a community fork called Ende

19 October 2026

The Deno team announced that they are joining Cloudflare and will stop working on the Deno runtime in about one year. Deno is a program that runs JavaScript and TypeScript code. Ryan Dahl, who created Deno, said the decision was shared by the team, and that Deno got pulled into copying Node.js too closely, so it stopped solving big problems. The team promised monthly releases for one more year, and Deno stays under the MIT license, which means anyone can copy it and keep working on it. A developer named P. Webb is doing exactly that, with a fork called Ende, which means "end" in German. Ende will drop Node.js compatibility and also drop Deno Deploy, KV and Jupyter support. If you run Deno in production, you now have a clock on your current setup, and you need to plan a move to Node.js, Bun, or a fork. The Ende roadmap lists per-module permissions, sandboxes for untrusted code, post-quantum cryptography in Web Crypto, and better binary output. P. Webb is aiming for a soft launch of Ende in December 2026, and has put up a placeholder site with a mailing list.

Sphinx, a free Git hook, quizzes you about your AI agent's code before you push

18 October 2026

A developer released Sphinx, a free and open source Git hook that checks if you understand the code your AI coding agent wrote. A Git hook is a small program that Git runs automatically at certain moments, and Sphinx runs when you push to a branch you marked as protected. Sphinx reads the diff, which is the list of changes, and asks you a question about what the code does when something goes wrong. One example in the demo asks what happens when Stripe retries a webhook after a payment call fails. Answer correctly and the push continues. Answer wrong and Sphinx explains why, then gives you a new scenario. You install it with npm install -g sphinx-understand and then sphinx install. It works with Codex, Claude Code, Cursor, OpenCode, Pi, or plain Git, and it needs Node 22.19 or newer on macOS, Linux, or WSL. Your answers are never sent to the coding agent, and Sphinx never opens .env files or keys. If you are in a hurry, the sphinx yolo command lets the push through, but every skip is written to a log. The post reached the Hacker News front page with 223 points and 76 comments.

Some parts of the application programming interface, or API, are still very low level, so simple tasks can take more code than expected.

ranet3 released: a userspace IPsec mesh SD-WAN that routes by latency

18 October 2026

A new tool called ranet3 was shared on Lobsters. ranet3 builds a mesh VPN, which is a private network where every machine can talk directly to every other machine. It runs fully in userspace, so it does not need special kernel support. ranet3 uses only standard protocols: IKEv2 for the handshake, ESP over UDP for the data, Babel for routing, and SRv6 for steering traffic through chosen waypoints. The handshake also supports hybrid ML-KEM, a key exchange built to resist future quantum computers. The code is on GitHub under the FSL-1.1-ALv2 and Apache-2.0 licenses. The practical gain is interoperability. Tools like Tailscale, NetBird, ZeroTier and Nebula only accept machines running their own agent. ranet3 peers with any router or switch that speaks IKEv2 with Ed25519 keys, Babel and SRv6, and the project reports tested interoperability with strongSwan, BIRD and the Linux kernel. Babel also measures round trip time on every link and moves traffic through a relay when the direct link gets slower. On two Dell PowerEdge C6420 hosts with 10 Gbit/s links, kernel WireGuard held 5.1 to 5.4 Gbit/s one way and kernel IPsec held 4.0 to 4.7 Gbit/s. One more detail matters for Mac users: segment routing works on macOS too, because ranet3 does the work in userspace instead of asking the XNU kernel, which has no support for it.

pgBackRest 2.60.0 adds strict page checksum errors and GCS Workload Identity support

18 October 2026

The pgBackRest community released version 2.60.0 on October 18, 2026. pgBackRest is a backup and restore tool for PostgreSQL databases. The biggest change is a new option called checksum-page-error. A page checksum is a small check value stored inside each database page, used to prove the page is not damaged. From now on, the restore command stops with an error if any restored file has a bad page checksum, and the expire command refuses to delete old backups if the oldest kept backup has checksum errors. The release also adds support for Google Cloud Storage Workload Identity Federation, which lets pgBackRest log in to Google Cloud without a stored key file. Other work includes prefetching multi-file reads from object stores, OpenSSL 4 support, and builds on illumos. If the new strict behaviour breaks your restore, set checksum-page-error=n to get a warning instead of an error. One more note for people building from a git checkout: the build now needs PyYAML instead of libyaml, though the release tarball needs neither.

pg_hint_plan 1.9.0 released with PostgreSQL 19 support and final PostgreSQL 14 update

18 October 2026

The pg_hint_plan team released version 1.9.0. pg_hint_plan is an extension for PostgreSQL, the open source database. The extension lets you change how PostgreSQL runs a query by writing hints inside SQL comments. A hint is a short instruction that tells the database which plan to use, for example which index to read or which join method to pick. Version 1.9.0 works with PostgreSQL 19 and adds support for path generation strategies (PGS). The team also shipped smaller updates for older databases: 1.8.1 for PostgreSQL 18, 1.7.2 for PostgreSQL 17, 1.6.3 for PostgreSQL 16, 1.5.4 for PostgreSQL 15, and 1.4.5 for PostgreSQL 14. These updates fix an infinite loop in the hint parser when a string holds more than one query. If you use pg_hint_plan to force a slow query into a faster plan, that hang can freeze a session, so the fix is worth taking. Version 1.4.5 is the last planned release for PostgreSQL 14, so teams still on that version need an upgrade plan.

Ollama 0.40.6 fixes leftover Windows processes and adds q2_0 model file support

17 October 2026

Ollama, a tool that lets you run large language models (LLM) on your own computer, has released version 0.40.6. The release has four changes. On Windows, Ollama no longer leaves behind orphaned runners, which are model processes that keep running after they should have stopped. Ollama now supports the q2_0 tensor and file types in GGUF, the file format that holds model weights on disk; q2_0 stores each number in about two bits, so the model file is much smaller. A feature called clef was launched in Ollama's cloud. The --ask mode now uses identifiers for its question keys instead of the question text. The Windows fix matters most in daily work, because orphaned runners hold on to memory and graphics card memory and can block the next model you try to load.

vLLM ships version 0.32.0 with a macOS build fix in the Rust frontend

18 October 2026

The vLLM project has published release v0.32.0. vLLM is an open source library that serves large language models, which means it runs a model and answers requests from other programs. The change named at the top of these release notes is a bug fix in the Rust frontend, the part of vLLM written in the Rust language that accepts incoming network connections. The fix makes that code read the address family of a listener socket it was handed by the operating system, instead of assuming one. A listener socket is the open port that waits for connections, and the address family tells it whether the address is IPv4 or IPv6. Before the fix, the build failed on macOS. If you develop or test vLLM on a Mac, you can now compile it again. The full list of changes sits in the release notes on the vLLM GitHub page.

ORIB browser extension brings back the old Reddit layout on www.reddit.com

17 October 2026

A developer named rajtilakjee released ORIB, a browser extension that replaces the current Reddit website with the classic old Reddit design. ORIB uses Manifest V3, which is the current rulebook Chrome requires for extensions. The extension runs a content script on any www.reddit.com page and rebuilds the page from Reddit's public JSON data, which is the plain data format Reddit already serves. You get the subreddit bar, the blue header, the sidebar, and threaded comments. Voting, saving, hiding, commenting, and submitting all work through your normal Reddit login. Keyboard shortcuts copy the style of Reddit Enhancement Suite, and pressing Shift and question mark shows the list. Some pages stay on the new design, including chat, settings, polls, moderation, and messages. The code is on GitHub, so you can install it right now by turning on Developer mode and choosing Load unpacked. Version 0.1.0 is the build prepared for the Chrome Web Store and Firefox Add-ons.
